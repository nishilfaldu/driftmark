Two pull requests to Streamdown

Streamdown is Vercel's React component that shows AI answers as they stream. #685 fixes a bug where one stray [ damages the text after it. #689 makes each streaming update cheaper. The demos on this page run the real code from both pull requests.

#685 · Bug fixOpen
fix(remend): complete links only in the current block A stray [ in an earlier paragraph no longer adds junk to later text, or hides it.
#689 · PerformanceOpen
perf(streamdown): repair only the end of a streaming message Repairs only the last two blocks on each update. Up to 11% less main-thread work.
First, how Streamdown works

One string, repaired on every update

The model sends one long string of Markdown. A blank line starts a new block: a paragraph, a list, a code block. In the demos, ↵ marks a line break.

Streamdown shows the answer again after every few words. The newest words are often unfinished, like **bold te or [the setup gu. So before each update, Streamdown passes the string through remend. Remend completes what is still open. It adds the closing **, or a placeholder address ](streamdown:incomplete-link), so a half-written link already shows as a link.

#685 · remend link fix

A stray [ damages the text after it

Link text can't continue past the end of a paragraph, list item, heading or table row. But remend looks for an unclosed [ in the whole message. If it finds one in an earlier block, it adds ](streamdown:incomplete-link) to the end of the newest text. If the bracket starts an unfinished address, it drops everything after it.

Stray brackets are common in normal answers: a math range like [0, 1), a citation like [1, a[i in prose, or a link whose ) the model forgot.

The fix: look only at the current block

        

          
A new helper, findLastInlineBlockStart, finds where the current block starts. It reads backwards from the end and stops at the first blank line, fence, thematic break, heading, list item or table row. So its cost depends only on the last block.

          
When remend looks for an unfinished link or image to complete, it now treats any [ or ]( before that point as plain text.

        #689 · streaming speed-up
        
Each update repaired the whole message again

        

          
On every streaming update, Streamdown runs remend over the whole message, plus three regex checks for footnotes and link definitions. So each update costs more than the one before.

          
With #670 and #685, remend only completes syntax in the last block. It does not change the blocks before it. So the repair of those blocks is wasted work.

          
This pull request repairs only the end of the message: the last two blocks. Streamdown remembers where the blocks before them end, the stable length, and does not repair that text again.

The stable length moves only when remend changed nothing

        

          
Two texts exist on each update: the text the model sent, and the repaired text. Streamdown splits the repaired text into blocks. Remend can add a closer that the block parser reads as a new block. For example, after # Three [link and a line break, it adds ](streamdown:incomplete-link) on its own line. The repaired text then has one block more than the model sent, which would put the stable length one block too late.

          
When remend changes nothing, the two texts are the same, so the stable length is correct. Remend changes nothing on 79–91% of updates, so this rule costs almost nothing.

Why it waits for #670 and #685

        

          
Repairing only the end gives the same output as repairing everything only when remend completes syntax in the current block alone. Today it doesn't. Below, two unrelated ** in earlier paragraphs pair with each other, so a full repair adds nothing. Repairing only the end sees one ** and adds a closer that readers would see.

          
#670 does block-only repair for bold and italic, and #685 for links. With both, the two ways match.
